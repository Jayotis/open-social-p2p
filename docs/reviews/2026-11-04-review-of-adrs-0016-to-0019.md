# Review of ADRs 0016 to 0019

**Date:** 2026-11-04, and the ADRs revised after it on 2026-11-05. **Read against:** `main` at `a2abaf4`. This checks the drafts against the code and outside sources. Nothing was built or run for it. All four ADRs stay Proposed.

## What it found, and what changed

| ADR | Found | Changed |
| --- | --- | --- |
| [0016](../decisions/0016-machine-acquaintances.md) | Fake machines get no access, but under many names they can still crowd out honest ones, so a node stops meeting anyone else: an eclipse | A short section on it: ADR 0015's limits, and three more proposed. Stage A's gate adds fakes under several keys referring one another. A node whose only start is hostile is a stated limit |
| [0017](../decisions/0017-one-hop-forwarding.md) | Sharing an earned peer doesn't make it a forwarder with upload to spare. A forwarder can't see what it carries | Stage A counts only forwarders that said yes and have upload left, and reports the upload added to their homes. A forwarder checks both ends, not the contents |
| [0018](../decisions/0018-earned-direct-connections.md) | Restarting a router often keeps the same address. Knowing the account is enough to go after it; a real name isn't needed. Three tiny files aren't real work. `reset` left peers approved by hand connected | The harm table and the way out say so. Layer 4 needs a minimum of checked bytes. `reset` sets the rule to `nobody`. The price check tries tiny files and a fast host aimed at one node. Setup still recommends yes once the tests pass |
| [0019](../decisions/0019-taking-posts-and-media-down.md) | A resharer can't pass the author's `Delete` on unchanged: sync would skip it. Tombstones that expire let a deleted post come back. A revocation can't bring back what no node still holds | A `ForwardDelete` signed by the resharer, carrying the author's `Delete`. Tombstones kept for good. A daily `GetObjects` check for reshares without a follow. A post a thief deleted comes back only where the owner's node still has it |

## Checked in the code

Functions are named rather than lines, as lines move.

| Where | What it does | What follows |
| --- | --- | --- |
| [`sync.rs`](../../crates/osp-node/src/sync.rs), `sync_follow` | Skips any outbox entry not signed by the account being followed | The author's `Delete` can't travel unchanged in a resharer's outbox |
| `sync.rs`, `sync_follow` | Accepts at most two carried objects for each entry on a page | A forward carrying one `Delete` fits |
| `sync.rs`, `BACKFILL`, `MAX_NEW_PER_DAY` | A new follow starts at the latest 100 entries. After that, sync reads on from where it stopped, and stops for the day at 500 new objects | A follower that was offline still reads every delete. Behind a flood of posts, a delete waits a day |
| [`social.rs`](../../crates/osp-node/src/social.rs), `GetOutbox` | Carries reshares' posts and their authors' profiles | The receiving side must accept a carried `Delete` too |
| [`directory.rs`](../../crates/osp-node/src/directory.rs), `take_page`; [`db.rs`](../../crates/osp-node/src/db.rs), `keep_found` | A reader replaces a person's found posts with each new listing of them, and drops machine records for now | A deleted post leaves a reader's search at its next read. ADR 0015's step 3 starts at `take_page` |
| [`node.rs`](../../crates/osp-node/src/node.rs), `resign_own_objects` | Signs the whole outbox again when the key changes | It signs the owner's own deletes again. A thief's aren't in that outbox unless the thief had the node |
| [`endpoints.rs`](../../crates/osp-node/src/endpoints.rs), `DirectGate`; [direct endpoint tests](../testing/direct-endpoint.md) | Refuses anyone arriving through a relay on the first packet. Someone coming straight to an address may be told the node's other addresses | ADR 0018's handover keeps that gap, and now says so |
| [`machine.rs`](../../crates/osp-proto/src/machine.rs) | Has `Hello` and `Listing`, not `Known` | ADR 0015's step 3 is still to come |

## Sources

These informed the review. None of them tests OSP.

- [Heilman et al., *Eclipse Attacks on Bitcoin's Peer-to-Peer Network*, USENIX Security 2015](https://www.usenix.org/conference/usenixsecurity15/technical-sessions/presentation/heilman): an attacker can fill a node's connections and control what it sees. It shows the risk; its costs don't carry over to OSP over Tor.
- [RFC 4732, section 2.7](https://www.rfc-editor.org/rfc/rfc4732.html#section-2.7): flooding a link is a known way to cut someone off.
- [RFC 2131, section 4.4.2](https://www.rfc-editor.org/rfc/rfc2131.html#section-4.4.2): a restarting DHCP client asks for the address it had, so a router restart often keeps it. It says nothing of how often ISPs change addresses.
- [MaxMind on geolocation accuracy](https://support.maxmind.com/knowledge-base/articles/maxmind-geolocation-accuracy): an IP address gives a rough location, not a household.
- [ActivityPub, section 7.4](https://www.w3.org/TR/activitypub/#delete-activity-inbox): only an object's owner can delete it, and nothing makes other servers comply. The same holds for OSP.
- [IPFS compact denylist format, section 4.3](https://specs.ipfs.tech/compact-denylist-format/#43-privacy-and-user-control): a hash of each hash keeps a list from being a catalogue, but someone holding a file can still check whether it's listed.

## What comes next

1. **ADR 0015's step 3,** as accepted, with ADR 0016's three added rules (decided 2026-11-05).
2. **ADR 0019's step 1, deleting a post,** which it proposes for before the invited alpha. The roadmap gets it when the alpha is next planned.
3. **Measuring relays,** ADR 0014's "measuring media's default", which ADRs 0017 and 0018 both wait on.
4. **After the alpha:** earned direct connections, then forwarding only if its stage A says it's worth it.
